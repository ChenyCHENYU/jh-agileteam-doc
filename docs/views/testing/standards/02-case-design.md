# 用例设计标准

> 📦 来源：`wl-skills-test` v0.11.0 · `standards/02-case-design.md` · 可判定条目由 `wl-skills-test audit`（T 系列）与 `gate` 自动执行。


## 适用范围

本标准适用于测试团队所有功能测试用例的编写与评审。所有用例必须符合本标准的要素与分级，否则不予入库。

## 用例分级

| 等级 | 含义 | 覆盖要求 |
| --- | --- | --- |
| P0 | 主干功能、核心流程 | 必须 100% 覆盖，进入冒烟套件 |
| P1 | 重要功能、高频路径 | 必须覆盖，全量执行 |
| P2 | 次要功能、低频路径 | 应覆盖，可按风险裁剪 |
| P3 | 边界、异常、UI 细节 | 视风险补充 |

## 覆盖密度规则

| 规则 | 要求 |
| --- | --- |
| 功能点用例数 | 每个功能点不少于 10 条用例 |
| 用例与工作量匹配 | 1 天编制 ≥ 50 条用例 |
| 设计方法 | 以场景描述法为主，辅以边界值、等价类 |

## 用例要素

每条用例必须包含以下要素，缺一不可：

| 要素 | 说明 |
| --- | --- |
| 编号 | 全局唯一，按模块前缀 + 序号 |
| 名称 | 一句话描述用例意图 |
| 等级 | P0 / P1 / P2 / P3 |
| 分组 | 所属功能模块 |
| 子模块 | 细分功能点 |
| 前置条件 | 执行前必须满足的状态 |
| 步骤 | 有序、可复现的操作步骤 |
| 预期结果 | 可验证的明确结果 |
| 类型 | 正向 / 反向 / 异常 / 边界 |
| 编写人 | 责任人 |
| 编写时间 | 日期 |

## 示例

| 编号 | TC-LOGIN-001 |
| --- | --- |
| 名称 | 正确账号密码登录成功 |
| 等级 | P0 |
| 分组 | 登录模块 |
| 子模块 | 账号登录 |
| 前置条件 | 账号已注册且未锁定 |
| 步骤 | 1. 打开登录页 2. 输入正确账号 3. 输入正确密码 4. 点击登录 |
| 预期结果 | 跳转首页，用户信息正确 |
| 类型 | 正向 |
| 编写人 | 张三 |
| 编写时间 | 2026-08-04 |

## 用例编写要求

1. 步骤必须可复现，避免"点击相关按钮"等模糊描述。
2. 预期结果必须可验证，禁止"正常显示"等不可量化表述。
3. 一条用例只验证一个意图，禁止多条预期结果堆叠。
4. 反向用例必须明确预期错误提示文案或状态。
5. 涉及数据的用例必须说明数据准备方式。

## 注意事项

1. 用例评审必须三方到场（测试 + 开发 + 产品），评审通过率 100% 才能转测。
2. 用例库随版本演进，废弃用例标记归档而非删除。
3. 用例与需求双向追溯，需求变更必须同步更新用例。
4. 自动化用例与手工用例分库管理，避免混淆。
