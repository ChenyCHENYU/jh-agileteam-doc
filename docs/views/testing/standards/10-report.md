# 测试报告规范

> 📦 来源：`wl-skills-test` v0.11.0 · `standards/10-report.md` · 可判定条目由 `wl-skills-test audit`（T 系列）与 `gate` 自动执行。


## 适用范围

本规范适用于版本测试报告的编写与上线验证。测试报告是版本质量与上线决策的依据，必须按本规范模板输出。

## 测试报告模板

测试报告必须包含以下章节：

| 章节 | 内容 |
| --- | --- |
| 1. 版本概述 | 版本号、迭代目标、测试范围 |
| 2. 测试环境 | 环境地址、版本、数据说明 |
| 3. 测试进度 | 计划与实际开始 / 结束时间 |
| 4. 用例执行情况 | 用例总数、执行数、通过率 |
| 5. 缺陷统计 | 缺陷数、分级分布、关闭率 |
| 6. 质量门禁 | DI、DI 密度、严重关闭率、模块收敛 |
| 7. 风险与遗留 | 未关闭缺陷、已知风险 |
| 8. 上线结论 | 是否建议上线、预警等级 |
| 9. 上线验证点 | 上线后需验证的关键点 |

## 用例执行情况

| 指标 | 说明 |
| --- | --- |
| 用例总数 | 本次迭代用例总数 |
| 执行数 | 实际执行用例数 |
| 通过率 | 通过用例 / 执行用例 |
| 阻塞用例 | 因缺陷无法执行的用例 |

按严重程度统计缺陷分布，并给出关闭率：

| --- | --- | --- | --- |
| 致命 | | | |

## 质量门禁结论

引用质量门禁规范，给出 4 项指标达成情况：

| 指标 | 要求 | 实际 | 达成 |
| --- | --- | --- | --- |
| DI 趋势 | ≤ 10% | | |
| 严重关闭率 | 100% | | |
| DI 密度 | < 0.3 | | |
| 最差模块收敛 | ≤ 20% | | |

## 上线结论

| 结论 | 条件 |
| --- | --- |
| 建议上线 | 绿色预警，全部指标达标 |
| 有风险上线 | 黄色预警，需说明风险与规避措施 |
| 不建议上线 | 红色预警，关键指标超标 |

## 上线验证点

上线后必须验证的关键点清单：

- 核心主流程可用（对应冒烟套件）。
- 本次迭代新增功能可用。
- 上线变更涉及的老功能无回归。
- 接口可调通，无 5xx。
- 关键数据正确（如金额、状态）。

## 线上验证流程

| 步骤 | 内容 | 要求 |
| --- | --- | --- |
| 1 | 上线后冒烟 | 冒烟套件全过 |
| 2 | 按验证点逐项验证 | 记录结果 |
| 3 | 线上数据核对 | 与测试一致 |
| 4 | 验证数据清理 | 及时删除 |
| 5 | 出验证结论 | 上报结论 |

线上验证总时长不超过 1.5 小时。

## 线上验证数据清理

| 规则 | 要求 |
| --- | --- |
| 数据标识 | 验证产生的数据以 AT_ 前缀标识 |
| 清理时机 | 验证完成后立即清理 |
| 清理记录 | 记录清理的数据项 |
| 禁止留存 | 不得在生产环境留存测试数据 |

## 注意事项

1. 测试报告必须客观真实，不得隐瞒缺陷或美化数据。
2. 上线结论需测试负责人签字确认。
3. 线上验证发现缺陷按缺陷管理规范处理，优先级提高。
4. 报告归档保存，便于后续版本追溯与复盘。
5. 线上验证完成后必须出验证结论，不得验证后不汇报。
