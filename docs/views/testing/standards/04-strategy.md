# 测试策略设计

> 📦 来源：`wl-skills-test` v0.11.0 · `standards/04-strategy.md` · 可判定条目由 `wl-skills-test audit`（T 系列）与 `gate` 自动执行。


## 适用范围

本规范适用于迭代测试计划中的策略制定，确定测试模型、测试类型组合与测试维度覆盖。

## 测试模型

采用敏捷迭代增量模型：

| 特征 | 说明 |
| --- | --- |
| 增量交付 | 按功能点增量开发、增量测试 |
| 迭代回归 | 每个迭代保留 50% 全量回归 |
| 持续集成 | 配合 CI 进行冒烟与自动化回归 |
| 风险驱动 | 高风险模块优先测试，资源向 P0 倾斜 |

## 测试类型组合

| 类型 | 目的 | 占比建议 |
| --- | --- | --- |
| 功能测试 | 验证功能正确性 | 主体，占比最大 |
| 系统测试 | 验证模块集成、端到端流程 | 覆盖跨模块主流程 |
| 探索性测试 | 发现未知缺陷、补充覆盖盲区 | 高风险模块必做 |

三者组合使用：功能测试保证覆盖、系统测试保证集成、探索性测试查漏补缺。

## 测试维度

每个功能点必须从以下 5 个维度评估覆盖：

| 维度 | 关注点 |
| --- | --- |
| 功能 | 业务逻辑正确、输入输出符合预期 |
| 界面交互 | 布局、提示、按钮、响应一致 |
| 权限 | 角色权限边界、越权拦截 |
| 数据 | 数据增删改查、数据一致性、持久化 |
| 兼容性 | 浏览器、分辨率、端类型兼容 |

## 策略制定步骤

1. 分析需求，识别功能点与风险点。
2. 按风险对功能点分级（P0~P3）。
3. 确定测试类型组合与维度覆盖。
4. 评估工作量，分配资源与排期。
5. 明确准入（冒烟通过率 95%）与准出（DI、缺陷关闭率）门槛。
6. 制定自动化与性能测试的介入时机。

## 示例（某后台管理系统迭代）

| 功能点 | 等级 | 维度覆盖 | 测试类型 |
| --- | --- | --- | --- |
| 用户管理 | P0 | 功能 / 权限 / 数据 | 功能 + 自动化 |
| 列表导出 | P1 | 功能 / 数据 / 兼容性 | 功能 + 探索性 |
| 主题切换 | P2 | 界面交互 / 兼容性 | 功能 |

## 资源分配原则

| 等级 | 资源倾斜 |
| --- | --- |
| P0 | 优先全量 + 自动化覆盖 |
| P1 | 全量执行 |
| P2 | 按风险裁剪 |
| P3 | 视资源补充 |

## 注意事项

1. 策略必须写进测试计划并在评审会同步，不得口头约定。
2. 探索性测试不是随意测试，需提前定义探索目标与时间盒。
3. 兼容性维度需结合产品实际用户端分布确定范围，不盲目全测。
4. 策略在迭代中可根据风险动态调整，但调整需记录原因。
