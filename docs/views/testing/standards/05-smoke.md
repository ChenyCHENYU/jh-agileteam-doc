# 冒烟测试规范

> 📦 来源：`wl-skills-test` v0.11.0 · `standards/05-smoke.md` · 可判定条目由 `wl-skills-test audit`（T 系列）与 `gate` 自动执行。


## 适用范围

本规范适用于开发提测前的自测与测试团队转测前的冒烟验证。冒烟是转测的硬性门槛，未达标准的版本必须打回。

## 转测门槛

| 门槛 | 要求 |
| --- | --- |
| 冒烟通过率 | ≥ 95% |
| 自测清单 | 开发必须完成并提交自测清单 |
| 致命 / 严重缺陷 | 0 个 |
| 环境可用 | 测试环境可访问、配置正确 |

冒烟通过率不足 95%，测试有权拒绝转测，开发需修复后重新提测。

## 自测清单

开发提测前必须完成自测清单并随版本提交：

- 主干功能可正常进入。
- 核心接口可调通，无 5xx 错误。
- 数据库可正常读写。
- 前端无控制台阻断性报错。

## 冒烟套件规模

| 版本复杂度 | 套件用例数上限 |
| --- | --- |
| 简单 | ≤ 8 条 |
| 中等 | ≤ 15 条 |
| 复杂 | ≤ 25 条 |

套件规模按版本复杂度选择，不得超过上限，保证冒烟可在 1.5 小时内完成。

## 纳入规则

冒烟用例必须同时满足以下条件：

| 规则 | 要求 |
| --- | --- |
| 等级 | 仅 P0 主干正向用例 |
| 步骤 | ≤ 5 步 |
| 稳定性 | 连续 3 次迭代稳定通过 |
| 类型 | 正向主流程，不含异常 |

## 排除规则

以下用例不得纳入冒烟套件：

| 排除类型 | 原因 |
| --- | --- |
| 异常用例 | 冒烟只验证主干可用 |
| 边界用例 | 非主干路径 |
| 高危操作用例 | 可能污染数据或破坏环境 |
| 依赖第三方用例 | 稳定性差，易误报 |

## 冒烟执行流程

1. 开发提测并提交自测清单。
2. 测试从冒烟套件中选取当前版本相关用例。
3. 执行冒烟，记录通过 / 失败。
4. 统计通过率，判定是否转测。
5. 通过则进入全量执行，不通过则打回。

## 示例

某中等复杂度版本，冒烟套件 12 条：

| 用例 | 结果 |
| --- | --- |
| 登录主流程 | 通过 |
| 创建订单主流程 | 通过 |
| 查询列表主流程 | 失败（接口报错） |
| ... | ... |

通过率 = 11 / 12 = 91.7% < 95%，判定不通过，打回开发。

## 注意事项

1. 冒烟套件应随版本演进维护，稳定的 P0 用例逐步纳入。
2. 冒烟失败必须明确原因并提交开发，不得自行绕过。
3. 冒烟结果作为转测记录归档，便于追溯。
4. 冒烟套件优先实现自动化，作为 CI 门禁。
