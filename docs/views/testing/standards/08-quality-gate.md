# 质量门禁

> 📦 来源：`wl-skills-test` v0.11.0 · `standards/08-quality-gate.md` · 可判定条目由 `wl-skills-test audit`（T 系列）与 `gate` 自动执行。


## 适用范围

本规范适用于上线判定、质量评估与质量预警。质量门禁用 DI 指标量化缺陷风险，作为版本能否上线的硬性标准。

## DI 计算公式

DI（Defect Index）用于衡量版本缺陷严重程度：

```
DI = 致命缺陷数 × 10 + 严重缺陷数 × 3 + 一般缺陷数 × 1 + 轻微缺陷数 × 0.1
```

| 严重程度 | 权重 |
| --- | --- |
| 致命 | 10 |
| 严重 | 3 |
| 一般 | 1 |
| 轻微 | 0.1 |

## DI 密度

DI 密度用于消除规模差异，便于跨版本比较：

```
DI 密度 = DI / 代码规模（千行）或 DI / 用例数
```

团队基线：DI 密度 < 0.3 视为合格。

## 缺陷来源分类

| 来源 | 说明 |
| --- | --- |
| 需求缺陷 | 需求不清晰、遗漏、歧义 |
| 设计缺陷 | 架构、接口设计不合理 |
| 编码缺陷 | 实现错误、逻辑漏洞 |
| 环境缺陷 | 配置、环境、第三方问题 |

缺陷录入时必须标注来源，便于根因分析与改进。

## 上线判定指标

版本上线必须同时满足以下 4 项指标：

| 指标 | 要求 |
| --- | --- |
| DI 趋势 | 较上一版本 ≤ 10%（不得恶化） |
| 严重缺陷关闭率 | 100% |
| DI 密度 | < 0.3 |
| 最差模块收敛 | 最差模块缺陷占比 ≤ 20% |

任一指标不达标，版本不予上线，需延期修复。

## 质量预警

根据 DI 与缺陷状态进行三级预警：

| 预警 | 条件 | 动作 |
| --- | --- | --- |
| 绿色 | 全部指标达标 | 正常上线 |
| 黄色 | 个别指标接近阈值 | 风险提示，加强回归 |
| 红色 | 关键指标超标 | 禁止上线，强制修复 |

判定规则：

- DI 趋势 > 10% 或 DI 密度 ≥ 0.3 → 黄色。
- 严重缺陷关闭率 < 100% → 红色。
- 最差模块缺陷占比 > 20% → 黄色。
- 出现未关闭致命缺陷 → 红色。

## 示例

某版本缺陷情况：

| 程度 | 数量 |
| --- | --- |
| 致命 | 0 |
| 严重 | 2 |
| 一般 | 5 |
| 轻微 | 10 |

DI = 0×10 + 2×3 + 5×1 + 10×0.1 = 12

若用例数 500，DI 密度 = 12 / 500 = 0.024 < 0.3，该项达标。

严重缺陷 2 个需全部关闭，关闭率达 100% 才能上线。

## 注意事项

1. DI 是趋势指标，必须与历史版本对比，单看绝对值无意义。
2. 严重缺陷关闭率指已验证关闭，非开发自述修复。
3. 最差模块收敛用于倒逼重点模块加强测试，避免缺陷集中。
4. 预警结果必须记录在测试报告中，作为上线决策依据。
5. 紧急上线需经产品 + 测试 + 开发三方评估并留痕，不得绕过门禁。
