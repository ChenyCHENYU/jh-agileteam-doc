# 用例设计方法

> 📦 来源：`wl-skills-test` v0.11.0 · `standards/03-case-method.md` · 可判定条目由 `wl-skills-test audit`（T 系列）与 `gate` 自动执行。


## 适用范围

本规范适用于测试用例设计的方法选型与落地。设计用例时应组合使用以下方法，确保主流程、分支、异常、边界全覆盖。

## 设计方法总览

| 方法 | 适用场景 | 产出重点 |
| --- | --- | --- |
| 场景法 | 业务主流程、多分支业务 | 主流程 + 分支 + 异常用例 |
| 边界值分析 | 数值、长度、范围输入 | 边界点用例 |
| 等价类划分 | 大量输入数据分类 | 有效 + 无效等价类用例 |
| 错误推测法 | 经验性高危操作 | 易错点用例 |
| 状态迁移法 | 多状态流转的业务 | 状态间迁移用例 |

## 场景法

通过基本流（主流程）和备选流（分支、异常）组合生成用例。

- 基本流：用户完成核心目标的正常路径。
- 备选流：分支条件、中断、异常恢复路径。

示例（订单支付）：

| 流 | 步骤 |
| --- | --- |
| 基本流 | 下单 → 选支付方式 → 支付成功 → 订单完成 |
| 备选流1 | 下单 → 选支付方式 → 余额不足 → 提示充值 |
| 备选流2 | 下单 → 选支付方式 → 支付超时 → 订单取消 |

## 边界值分析

针对输入范围的边界点设计用例，边界是最易出错的位置。

示例（密码长度 6-20 位）：

| 边界 | 取值 | 预期 |
| --- | --- | --- |
| 下界以下 | 5 位 | 拒绝 |
| 下界 | 6 位 | 通过 |
| 上界 | 20 位 | 通过 |
| 上界以上 | 21 位 | 拒绝 |

## 等价类划分

将输入划分为有效等价类和无效等价类，每类取代表性用例。

示例（手机号输入）：

| 类别 | 取值 | 预期 |
| --- | --- | --- |
| 有效等价类 | 11 位数字、首位为 1 | 通过 |
| 无效等价类 | 10 位、含字母、首位非 1 | 拒绝 |

## 错误推测法

基于经验列出易错点，针对性补充用例。

示例（表单提交）：

- 重复提交（连点两次提交按钮）
- 网络中断后恢复
- 并发操作同一资源
- 特殊字符（空格、emoji、SQL 关键字）

## 状态迁移法

对有状态流转的业务，绘制状态图后覆盖所有迁移路径。

示例（订单状态）：

| 当前状态 | 事件 | 迁移后状态 |
| --- | --- | --- |
| 待支付 | 支付成功 | 已支付 |
| 已支付 | 发货 | 已发货 |
| 已发货 | 确认收货 | 已完成 |
| 已完成 | 申请退款 | 退款中 |

## 方法组合建议

1. 主流程功能：场景法为主，等价类补充输入。
2. 表单 / 输入框：边界值 + 等价类为主。
3. 复杂业务流程：场景法 + 状态迁移法。
4. 历史高频缺陷模块：错误推测法补充。
5. 每个功能点至少覆盖正向、反向、异常三类用例。

## 注意事项

1. 单一方法无法保证覆盖率，必须组合使用。
2. 场景法产出的主流程用例应纳入冒烟套件。
3. 状态迁移法必须覆盖所有合法迁移，并补充非法迁移用例。
4. 错误推测法依赖经验积累，应建立团队缺陷库反哺用例设计。
