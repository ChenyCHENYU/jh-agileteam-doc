# 测试流程规范

> 📦 来源：`wl-skills-test` v0.11.0 · `standards/01-test-process.md` · 可判定条目由 `wl-skills-test audit`（T 系列）与 `gate` 自动执行。


## 适用范围

本规范适用于测试团队所有敏捷迭代的测试流程管理，覆盖迭代前、迭代中、迭代后三个阶段。所有测试人员必须按本规范执行，不得跳过或合并关键节点。

## 迭代前（需求评审）

| 节点 | 内容 | 产出 |
| --- | --- | --- |
| 需求评审 | 参与需求评审会，理解业务目标与边界 | 需求疑问清单 |
| 测试点 | 拆解功能点，识别风险点与依赖 | 测试点列表 |
| 工作量评估 | 评估用例数、执行轮次、回归范围 | 工作量评估表 |
| 测试计划 | 制定测试计划与里程碑 | 测试计划文档 |

## 迭代中（测试执行）

| 节点 | 内容 | 门槛 |
| --- | --- | --- |
| 用例编制 | 按用例设计标准编写 | 1 天 50 条 |
| 用例评审 | 测试 + 开发 + 产品三方评审 | 评审通过率 100% |
| 冒烟转测 | 开发自测 + 测试冒烟 | 冒烟通过率 ≥ 95% |
| 执行测试 | 第一轮全量 + 第二轮全量 | 两轮全量执行 |
| BUG 回归 | 开发修复后回归验证 | 回归工作量 = 50% 全量 |
| 产品验收 | 产品按验收点验收 | 验收通过 |
| 封版 | 冻结代码，产出封版清单 | 无未解决致命 / 严重缺陷 |

## 迭代后（上线与验证）

| 节点 | 内容 | 要求 |
| --- | --- | --- |
| 上线 | 配合上线，关注冒烟点 | 上线后冒烟通过 |
| 线上验证 | 按上线验证点验证 | 线上验证不超过 1.5h |
| 用户手册 | 更新用户手册 / 操作指引 | 手册与版本同步 |

## 核心量化规则

| 指标 | 规则 |
| --- | --- |
| 用例编制效率 | 1 天 ≥ 50 条用例 |
| 用例执行效率 | 1 小时执行 6 条用例 |
| 冒烟通过率 | ≥ 95% 才允许转测 |
| 测试轮次 | 两轮全量 + 一轮回归 |
| 回归工作量 | 全量工作量的 50% |
| 工作量计算 | 用例数 / 50 + 执行时长 / 6 + 回归 50% |

## 示例

某迭代需测试 5 个功能点，预估用例 250 条：

- 用例编制：250 / 50 = 5 人天
- 执行两轮全量：250 / 6 × 2 = 83.3 小时 ≈ 10.4 人天
- 回归（50%）：10.4 / 2 = 5.2 人天
- 合计：5 + 10.4 + 5.2 ≈ 20.6 人天

## 注意事项

1. 冒烟通过率不足 95% 必须打回开发自测，不得带病转测。
2. 回归测试穿插在两轮全量执行中，不单独作为一轮。
3. 封版后禁止代码改动，紧急修复需重新评估回归范围。
4. 工作量评估偏差超过 ±20% 需在复盘会说明原因。
5. 线上验证发现的缺陷按缺陷管理规范处理，不得口头沟通了事。
