## 五份文档的共同结构

每份宣贯文档遵循同一骨架，便于跨包对照阅读：

1. **宣贯目标与核心结论** — 一段统一认识 + 版本演进速览
2. **落地背景与现存问题** — 具体到代码/文档的痛点清单与根因判断
3. **方案定位与统一原则** — 不是什么/是什么、事实来源、管控方式
4. **整体工程架构** — 分层图与层级职责
5. **统一管控覆盖维度** — 逐条规范/规则展开
6. **Skill/工具全景** — 数量、能力、触发方式
7. **接入流程** — 新项目 / 存量整改 / 日常增量三种场景
8. **问题归属判断** — 决策树：改公共包、改本项目还是改契约
9. **全员执行要求** — 必须执行 / 明确禁止 / 允许但需评审
10. **角色职责 · 验收清单 · 反馈机制 · 落地价值 · 会议输出**
11. **附录** — 常用命令速查、规范与工程能力对应表

## 宣贯会后建议动作

1. 各角色按"我该从哪里开始"路径完成对应包的安装与 `doctor` 体检；
2. 按 [快速上手](/backend/quick-start)（后端）/ [前端快速上手](/frontend/quick-start/)（前端）跑通最小闭环；
3. 存量项目先做只读体检（`validate` / `audit` / `verify db`），拿报告再定整改计划；
4. 公共问题按各文档"问题归属判断"决策树归口，不在项目内打局部补丁。

## 反馈与更新

- 文档与包能力不一致时，按对应宣贯文档第十三章（反馈机制）提供版本、场景、复现样例；
- 每次包发版后，本目录随在线站点同步更新"当前核对版本"与能力变化。
